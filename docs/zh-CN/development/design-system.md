# 设计系统

[English](../../development/design-system.md) | [简体中文](design-system.md)

本指南整合了运行时 UI 约定和可选设计稿指南。应用样式是权威来源；设计稿用于设计和审阅，而不是独立的实现契约。

## 原则

- **主题感知：**每个共享界面和工具都必须同时支持亮色与暗色主题。
- **一致：**用途相同的控件使用相同的间距、形状、状态和措辞。
- **紧凑但可读：**DevToolBox 信息密度较高，但不能因此隐藏层级或缩小交互目标。
- **聚焦能力：**每个工具只呈现主要输入、操作和结果，不重复无关的应用外壳。
- **无障碍：**键盘焦点、对比度、错误状态和窄窗口行为都属于必须设计的一等状态。

## 权威来源

| 关注点                           | 来源                                     |
| -------------------------------- | ---------------------------------------- |
| 运行时颜色、字体、圆角和布局变量 | `core/renderer/theme/variables.css`      |
| 共享工具样式                     | `core/renderer/theme/toolkit.css`        |
| 共享 React 组件和 Hook           | `core/packages/ui/`                      |
| 工具级可复用布局模式             | `core/renderer/components/` 下的现有组件 |

当设计稿中的值与运行时变量不一致时，应更新设计稿或记录有意差异；不要为了匹配过时稿件而增加局部 CSS 覆盖。

## 运行时变量

### 颜色

使用语义变量，而不是直接写颜色值：

| 角色           | 变量                                                                                                                                     |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 表面           | `--bg-primary`、`--bg-secondary`、`--bg-tertiary`、`--bg-elevated`、`--bg-hover`                                                         |
| 边框           | `--border-default`、`--border-subtle`、`--border-emphasis`、`--border-focus`                                                             |
| 文本           | `--text-primary`、`--text-secondary`、`--text-tertiary`、`--text-quaternary`、`--text-disabled`、`--text-on-accent`                      |
| 强调和状态     | `--accent-primary`、`--accent-secondary`、`--accent-success`、`--accent-error`、`--accent-warning`                                       |
| 选中和信息状态 | `--state-selected-bg`、`--state-selected-border`、`--state-selected-text`、`--state-info-bg`、`--state-info-border`、`--state-info-text` |
| 代码语法       | `--syntax-key`、`--syntax-string`、`--syntax-number`、`--syntax-boolean`、`--syntax-null`                                                |
| 分类           | `--cat-dev`、`--cat-text`、`--cat-network`、`--cat-security`、`--cat-other`                                                              |

暗色主题值位于 `:root`，亮色主题覆盖值位于 `:root[data-theme='light']`。应按语义意图选择变量，而不是按当前颜色名称选择。例如，辅助文本应使用 `--text-tertiary`，而不是复制它当前的十六进制值。

可选择行、导航和选项卡片使用选中状态变量。`--accent-primary` 与 `--text-on-accent` 只用于实心主要操作。信息提示使用 `--state-info-*` 变量组，不要在组件中嵌入暗色表面值。共享浮层使用主题感知的阴影变量，不要直接写黑色阴影。

### 字体

- UI 字体：`--font-family`（Inter 和平台回退字体）
- 等宽字体：`--font-family-mono`（JetBrains Mono/Fira Code 和平台回退字体）
- 基础字号：`--font-size-base`
- 辅助字号：`--font-size-small`、`--font-size-xs`
- 标题字号：`--font-size-heading`、`--font-size-title`
- 正文行高：`--line-height-base`

代码、日志、序列化数据、哈希和面向机器的输出使用等宽字体。普通控件或说明文字不要使用等宽字体。

### 形状和布局

运行时变量定义了共享圆角、浮层阴影、侧边栏宽度、模块面板宽度和工作区最大宽度。请使用这些变量，不要在模块中重复定义尺寸。

局部间距遵循 4 px 节奏。常用间距和内边距为 4、8、12、16、20 和 24 px。选择能够保持分组关系和可读点击区域的最小值。

## 组件约定

### 按钮和操作

- 普通操作使用默认按钮，主要任务使用视觉上明显的主要按钮。
- 纯图标按钮保持正方形，并提供无障碍标签或工具提示。
- 提供悬停、按下、焦点可见和禁用状态。
- 将破坏性操作单独分组；数据无法恢复时要求用户确认。
- 操作行在窄窗口可能溢出时使用 `ResponsiveActions`。

### 输入框、文本区域和下拉框

- 含义无法从上下文直接判断时，始终显示标签。
- 占位符只作为示例，不能替代标签。
- 保持明显的焦点可见状态和清晰的无效/错误状态。
- 清除、复制、显示和搜索操作应位于一致的后缀位置。
- 编辑器类界面中的 Ctrl/Cmd+F 使用 `useTextSearch` 和 `SearchBar`。

### 卡片和列表行

卡片用于组织相关内容，不应包裹每一个单独字段。列表行通常把标题和辅助文字放在左侧，把状态或操作放在右侧。徽章只用于简短状态或版本信息，不用于长消息。

### 对话框

对话框需要清晰的标题、聚焦的内容和可预测的操作区域。主要操作在阅读顺序中放在最后。确认对话框必须明确说明会发生什么，以及操作是否可撤销。

### 分栏

双栏可调整工具使用 `useSplitPane`。分隔线必须容易发现，两侧都要保留可用的最小宽度；如果某一侧需要临时聚焦，应提供展开和恢复操作。

## 应用布局

桌面应用外壳包含三个概念区域：

1. 导航区选择仪表盘或工具分类。
2. 模块面板选择当前分类中的工具。
3. 内容工作区渲染当前页面或工具。

工具页面应使用 `ToolSection` 作为顶层容器。一个实用的工具页面通常包含：

- 包含标题、简短上下文和可选操作的页头；
- 包含主要交互的可滚动正文；
- 用于持久输入或执行控件的可选页脚。

不要在工具内部重复应用导航。较长说明放入帮助内容，工作区应保留给当前任务。

## 状态设计

设计并测试每个相关状态：

- 初始或空状态；
- 加载或运行中；
- 成功，并提供复制/导出操作；
- 责任输入附近的校验错误；
- 运行时或网络失败，并提供恢复建议；
- 能力被禁用或不可用；
- 长内容和窄窗口；
- 亮色和暗色主题。

日志和协议流应使用文字与颜色共同区分系统、发送、接收、警告和错误事件，不能只依赖颜色。

组件页面按照组合复杂度递增组织：

- **原子：**按钮、输入框、复选框、开关、徽章和图标；
- **分子：**搜索框、带标签控件、标签页组和列表行；
- **组织：**导航、模块面板、对话框、工具页头和分栏工作区。

推荐模板包括仪表盘、工具、模块/Marketplace、设置、全局搜索和代表性的工具页面。主参考使用 1440 × 900 桌面画框，并为响应式行为添加窄窗口变体。

本仓库不再提供内置设计文件生成器。如果外部维护设计稿，请让它与上方列出的运行时变量保持一致。

## UI 审阅清单

- 使用运行时变量，而不是组件私有颜色表。
- 两种主题都保持清晰的层级、对比度和可见焦点。
- 主要、破坏性、禁用、加载、空和错误状态表达清楚。
- 键盘操作和文本搜索行为一致。
- 工具布局在窄窗口下不会隐藏关键操作。
- 设计稿发生变化时，与运行时变量保持同步。
